# `swarmsim/world.py` — мир ★

**Назначение.** Среда из `docs/02`, раздел 2.1: границы территории, бесполётные зоны, карта
вероятности нахождения целей, сами цели (включая появляющиеся по ходу миссии),
обнаружение целей агентами и контроль жёстких ограничений (столкновения, геозоны).

**Импорты.** `math`, NumPy; из пакета — `geometry` (точка в многоугольнике, пересечение
отрезка с многоугольником, ограничивающий прямоугольник), `scenario.Scenario`,
`datatypes.WorldSnapshot`.

**Ключевые решения.**
- Мир **двумерный** (`docs/02`, антипаттерн 2: «все исследовательские вопросы решаются в
  2D»). Высота есть у агентов, но нужна только для GSD камеры и эшелонирования.
- Территория разбита на **сетку ячеек** `cell_size × cell_size` (по умолчанию 25 м). Сетка
  используется для карты вероятности, быстрой выборки целей по ячейке и карты покрытия.
- У мира **два своих генератора**: `rng` (строит мир) и `sensing_rng` (случайность
  обнаружения). Мир строится целиком в конструкторе, поэтому одинаков при одном зерне.

---

## `class World`

### `__init__(scenario, rng, sensing_rng, log=None)`
По шагам:
1. **Границы**: `bounds = (0, 0, W, H)` из `world.size`.
2. **Бесполётные зоны**: каждый многоугольник → массив NumPy `(K, 2)`; заранее считается
   его ограничивающий прямоугольник `_nofly_bbox` для быстрой предпроверки.
3. **Сетка**: `nx = ceil(W / cell)`, `ny = ceil(H / cell)`, площадь ячейки `A_cell = cell²`.
4. **Карта вероятности** `prior` (`_build_prior`).
5. **Все цели сразу**: начальные `world.targets` плюс все будущие из `world.new_targets`.
   Для каждой цели хранится:

| Массив | Смысл |
|---|---|
| `target_pos (M, 2)` | координаты |
| `target_appear (M,)` | время появления (0 для начальных) |
| `target_cell (M,)` | номер ячейки |
| `target_active (M,)` | уже появилась |
| `target_detected (M,)` | уже обнаружена |
| `target_t_detected (M,)` | когда обнаружена |
| `target_miss (M,)` | `Π(1 − Pd_k)` — вероятность **пропустить** цель после всех проходов над ней |

6. `coverage_miss` — то же, что `target_miss`, но для каждой ячейки: карта покрытия.
7. `_by_cell` — словарь «ячейка → список активных целей в ней», для быстрого
   обнаружения: не нужно перебирать все цели на каждом шаге.
8. Счётчики жёстких ограничений: `n_collisions`, `n_near_miss`, `n_geofence` и множества
   «текущих» нарушений (`_pairs_col`, `_pairs_nm`, `_geo_violators`) для подсчёта по фронту.

Почему все цели генерируются заранее: если бы новые цели генерировались в момент
появления, их положение зависело бы от того, сколько случайных чисел уже потрачено. Тогда
при другом распределителе мир был бы другим. Заранее — значит мир зависит только от зерна.

### `_cell_center(iy, ix) -> np.ndarray`
Центр ячейки `((ix + 0.5)·cell, (iy + 0.5)·cell)`.

### `_build_prior() -> np.ndarray (ny, nx)` — карта вероятности целей
- `kind: uniform` — все ячейки равновероятны.
- `kind: hotspots` — **смесь гауссиан**: `n` центров случайно в пределах территории, в каждой
  ячейке `Σ exp(−|x − c|² / 2σ²)`. Плотность нормируется и смешивается с равномерным фоном:
  `prior = (1 − background)·смесь + background / число_ячеек`. Это модель «неоднородной
  плотности целей» из `docs/01`, раздел 3.2 — условие, при котором рой должен выигрывать.
- Ячейки, **центр** которых в бесполётной зоне, обнуляются: целей там не ищем.
- Карта нормируется к сумме 1. Если всё закрыто зонами — `ValueError`.

### `_sample_targets(n) -> np.ndarray (n, 2)` — раскладка целей
Для каждой цели: выбрать ячейку с вероятностью `prior` (`rng.choice(..., p=prior)`), затем
точку равномерно внутри ячейки. Если точка попала в бесполётную зону (возможно у края
зоны), повторить, до 1000 попыток. Координаты обрезаются по границе мира.

### Геометрические методы

| Метод | Возвращает | Как |
|---|---|---|
| `cell_index(p)` | номер ячейки `iy·nx + ix` | целочисленное деление координат на `cell`, с обрезкой по краям |
| `in_bounds(p)` | внутри территории? | сравнение с `bounds` (края включительно) |
| `in_nofly(p)` | в бесполётной зоне? | сначала проверка bbox, потом метод луча `point_in_polygon` |
| `segment_is_free(a, b)` | отрезок допустим? | оба конца в границах **и** отрезок не пересекает ни одну зону (bbox-отсечение, затем `segment_intersects_polygon`) |

`segment_is_free` — готовый инструмент для валидатора плана R2 (SR-1, SR-6 из `docs/01`).

### `step(dt) -> list[int]`
Сдвигает `t` мира на `dt` и **активирует цели**, время появления которых наступило
(допуск `1e-9` против ошибок округления). Новые цели попадают в `_by_cell`, а в журнал
пишется событие `new_targets` — сигнал распределителю (FR-9).

### `observe(agent, sensor) -> list[int]` — обнаружение целей
Реализация модели обнаружения `docs/02`, раздел 3.3, для отрезка, который агент пролетел за шаг
(`prev_p → p`):
1. Если агент не в воздухе или стоял — ничего.
2. `W = sensor.swath_width(agent.alt)` — ширина полосы обзора на этой высоте. `W = 0`
   значит, что с этой высоты цели не разглядеть.
3. Отрезок режется на куски не длиннее половины ячейки. Для каждого куска берётся его
   середина, и так **длина пути `L` накапливается по ячейкам**. Обычно за шаг 0.1 с агент
   пролетает 1.2 м и остаётся в одной ячейке, но нарезка корректна и при больших шагах.
4. Для каждой пройденной ячейки:
   - `Pd = 1 − exp(−W·L / A_cell)` — вероятность обнаружения за этот проход;
   - `coverage_miss[ячейка] *= (1 − Pd)` — карта покрытия;
   - для каждой цели в ячейке: `target_miss *= (1 − Pd)`; если цель ещё не найдена, то
     она найдена с вероятностью `Pd` (одно случайное число из `sensing_rng`).
5. Для найденных — событие `target_detected`.

Почему накопление корректно. Произведение `Π(1 − Pd_k) = exp(−W·ΣL/A)`, то есть
несколько коротких проходов дают ровно то же, что один длинный. Формула не зависит от
`dt`. Это проверяет тест `test_observe_accumulates_pd_as_in_formula`.

Ограничение модели (намеренное, как в `docs/02`): «случайный поиск» не учитывает, где
именно в ячейке лежит цель относительно пути. Это консервативная оценка: реальная
«змейка» обычно работает лучше.

### `check_separation(agents) -> (новые_столкновения, новые_сближения)`
Проверка NFR-8/NFR-9, **векторно** через NumPy:
1. Берутся только агенты в воздухе; строятся матрицы горизонтальных расстояний `dh` и
   разниц высот `dz` (N×N).
2. Пара «на одном уровне», если `dz < vertical_separation` (3 м).
3. **Опасное сближение**: `dh < 2·min_separation` (10 м) на одном уровне.
   **Столкновение**: `dh < min_separation` (5 м) на одном уровне.
4. Python-цикл идёт **только по близким парам** (`np.nonzero`), а не по всем N², поэтому
   на 50 агентах это быстро.
5. Подсчёт **по фронту**: событие считается, когда пара *входит* в опасную зону, а не
   каждый шаг, пока она там. Иначе одно касание дало бы 30 «столкновений».

Результат копится в `n_collisions` и `n_near_miss`, события — в журнал.

### `check_geofence(agents) -> list[int]`
Для каждого агента в воздухе: пересёк ли отрезок шага бесполётную зону или вышел ли за
границы (`segment_is_free`). Тоже подсчёт по фронту → `n_geofence`, событие
`geofence_violation`.

### `snapshot(agents) -> WorldSnapshot`
Снимок мира с текущим временем мира. Ядро для распределителя использует свой
`SimLoop.snapshot(t)` с точным временем шага.

### Метрики мира

| Метод / свойство | Смысл |
|---|---|
| `n_active_targets` | сколько целей уже появилось |
| `detected_fraction()` | доля реально обнаруженных среди активных (случайная величина) |
| `expected_detected_fraction()` | **Pd-взвешенная доля**: среднее `1 − target_miss` по активным целям. По ней считается `T_detect` (определение из `docs/03`, раздел 4); она менее шумная, чем фактическая |
| `coverage_map()` | карта `1 − coverage_miss` размером `(ny, nx)` — какая доля каждой ячейки «просмотрена» |

## Что стоит развивать
- Движущиеся цели (обновлять `target_pos` в `step`).
- Ветер как поле `wind(p, t)`: тогда в энергии нужна воздушная скорость, а не путевая.
- Препятствия по высоте (здания), если появится 3D.
