# `swarmsim/agents/base.py` — агент и интерфейс движения ★

**Назначение.** Два уровня описания БПЛА:
1. **`MotionSource`** — «чем двигается аппарат»: физическая модель или реальный борт.
2. **`Agent`** — «как аппарат себя ведёт»: следует плану задач, следит за энергией,
   возвращается домой, обрабатывает отказы.

Такое разделение — ключевое решение `docs/02`, разделы 2.1 и 5.1: при переходе
«симуляция → PX4 SITL → железо» меняется только `MotionSource`, а логика агента остаётся.

**Импорты.** `math`, `abc` (абстрактный класс), `dataclasses`, `typing`, NumPy; из пакета —
`AgentState`, `Mode`, `TaskSet`, `TaskStatus`, `VehicleState`.

---

## `@dataclass(frozen=True) class MotionCommand` — уставка движения

| Поле | Смысл |
|---|---|
| `target` | точка, куда лететь (или `None`) |
| `speed` | желаемая скорость полёта к точке |
| `velocity` | прямая команда вектора скорости (или `None`) |

Конструкторы: `MotionCommand.goto(target, speed)`, `MotionCommand.set_velocity(v)`,
`MotionCommand.hold()` (стоп). Команда неизменяемая (`frozen`), поэтому фильтр
безопасности должен вернуть **новую** команду, а не испортить старую.

Два вида команд («в точку» и «скорость») соответствуют двум режимам PX4/MAVSDK:
`goto_location` и offboard `set_velocity`. ORCA из R2 будет выдавать именно команды
скорости.

## `class MotionSource(ABC)` — интерфейс источника движения

| Член | Смысл |
|---|---|
| `state -> VehicleState` | текущее состояние (позиция, скорость, курс, высота) |
| `step(dt, cmd) -> VehicleState` | **абстрактный**: продвинуть аппарат на `dt` под командой |
| `halt()` | обнулить скорость (посадка, отказ) |

Реализации: `KinematicMotion`, `DoubleIntegratorMotion` ([agents_kinematics.md](agents_kinematics.md)).
Будущая — `MavsdkMotion`.

## `class Agent` — поведение БПЛА

### Режимы (`Mode` из `datatypes.py`)
```
IDLE ──takeoff──► MISSION ──план кончился / низкий заряд──► RTL ──дома──► LANDED
                    │  ▲                                     │
                    │  └──── новый план (заряд в норме) ─────┘
                    └──► FAILED  (отказ или полный разряд; из любого режима в воздухе)
```

### `__init__(agent_id, motion, energy, capacity_j, reserve, home, v_cruise, arrive_radius, e_takeoff, e_land, log=None, safety=None)`
Сохраняет параметры. Начальное состояние: `IDLE`, заряд полный (`e_j = capacity_j`), план
пуст. Счётчики `energy_used_j` и `distance_m` нужны для метрик.

### Свойства

| Свойство | Смысл |
|---|---|
| `state`, `p`, `alt` | состояние из `MotionSource` |
| `airborne` | в воздухе: `MISSION` или `RTL` |
| `healthy` | не `FAILED` |

### `snapshot() -> AgentState`
Неизменяемая копия для распределителя: позиция, скорость, курс, высота, энергия и
ёмкость, исправность, режим, дом, крейсерская скорость, план, текущая задача. Это вектор
состояния `s_i = (p, v, ψ, e, h, σ)` из `docs/01`, раздел 2.2.

### `takeoff(t)`
Только из `IDLE`: списать `E_takeoff` → режим `MISSION` → событие `takeoff`.

### `set_plan(task_ids, tasks, t)` — принять план от распределителя
1. Отказавшим и севшим агентам план не меняется.
2. Из плана выбрасываются выполненные и проваленные задачи.
3. Если текущая задача **не** вошла в новый план, она освобождается, но только если агент
   всё ещё её владелец. Проверка владельца важна: если задачу уже отдали другому агенту,
   освобождение сбросило бы чужое назначение. С ней результат не зависит от порядка, в
   котором ядро обходит агентов.
4. Задачи старого плана, не вошедшие в новый, освобождаются (тоже с проверкой владельца).
5. Если текущая задача в новом плане, она продолжается (не начинается заново) и убирается
   из очереди.
6. Новым задачам: `owner = self.id`, статус `ASSIGNED` (или остаётся `IN_PROGRESS`).
7. Если агент возвращался домой, потому что план кончился, а заряд в норме, — снова в
   `MISSION`.
8. Событие `plan`.

### `fail(t, reason, tasks) -> list[int]`
Отказ: освободить все задачи (`release_all`) → `FAILED` → скорость в ноль → событие
`agent_failed` со списком освобождённых задач. Возвращает этот список.

### `release_all(tasks, t, reason) -> list[int]`
Освобождает текущую задачу и весь план (только те, где агент — владелец и которые не
выполнены). Каждая получает статус `UNASSIGNED`, `owner = None` и событие
`task_released` с причиной. Именно это событие распределитель R2 ловит в `should_trigger`.

### `step(t, dt, neighbors, tasks)` — один шаг агента
```
prev_p = p                                  ← нужен миру для observe() и геозон
если не в воздухе — выход
_check_battery(t, tasks)                    ← не пора ли домой
cmd = _command(t, tasks)                    ← куда лететь
если есть фильтр безопасности: cmd = safety.filter(snapshot(), cmd, neighbors)
state = motion.step(dt, cmd)                ← физика
distance_m += пройденный путь
_consume(P(|v|)·dt)                         ← энергия по модели Zeng
если жив: _progress(t+dt, tasks)            ← достиг ли точки / дома
```

### `energy_to_home() -> float`
Оценка энергии на возврат: `energy_for_distance(|home − p|, v_cruise) + E_land`. Прямая
линия на крейсерской скорости — простая, но достаточная оценка. Запас даёт резерв.

### `_check_battery(t, tasks)` — правило возврата
Только в режиме `MISSION`:
```
если  e − energy_to_home() < reserve · capacity   →  RTL
```
То есть после возвращения домой должно остаться не меньше `reserve` (20 %) ёмкости —
ограничение `E_i ≤ e_i·(1 − reserve)` из `docs/01`, раздел 2.2. При срабатывании задачи
освобождаются (`low_battery`), флаг `low_battery = True` не даёт снова взять задачи,
событие `low_battery_rtl`. Тест `test_low_battery_triggers_rtl` проверяет, что с маленькой
батареей агенты уходят домой **до** полного разряда.

### `_command(t, tasks) -> MotionCommand` — выбор цели
В `MISSION`:
- если текущей задачи нет, взять следующую из плана, пропуская чужие и выполненные.
  Задача → `IN_PROGRESS`, `t_start`, номер точки `wp_idx = 0`, событие `task_started`;
- если план пуст → `RTL`, событие `plan_complete_rtl`;
- иначе → `goto(текущая_точка_маршрута, v_cruise)`.

В `RTL` → `goto(home, v_cruise)`.

### `_progress(t, tasks)` — продвижение по маршруту
- `MISSION`: если до текущей точки ≤ `arrive_radius` (2 м) — следующая точка. После
  последней точки задача `DONE`, `times_done += 1` (для контроля дублей `N_dup`), `t_done`,
  событие `task_done`.
- `RTL`: если дома — `LANDED`, скорость ноль, списать `E_land`, событие `landed`.

### `_reached(target) -> bool`
Расстояние до точки ≤ `arrive_radius`. Радиус нужен, потому что двойной интегратор
подходит к точке асимптотически, а не попадает в неё ровно.

### `_consume(joules, t)`
Списать энергию. Если заряд ≤ 0 — `FAILED`, событие `battery_depleted`. Задачи такого
агента освобождает ядро (в `SimLoop.run`), потому что здесь нет доступа к списку задач.
