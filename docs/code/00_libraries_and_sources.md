## 3. Методики и статьи — по модулям

### 3.1. Энергия мультиротора — `agents/energy.py` ★

**Источник:** Y. Zeng, J. Xu, R. Zhang, *"Energy Minimization for Wireless Communication With
Rotary-Wing UAV"*, IEEE Transactions on Wireless Communications, vol. 18, no. 4, 2019.
Формула мощности горизонтального полёта `P(V)` (раздел о модели энергопотребления) и таблица параметров
(`P0 = 79.86 Вт`, `Pi = 88.63 Вт`, `U_tip = 120 м/с`, `v0 = 4.03 м/с`, `d0 = 0.6`,
`ρ = 1.225 кг/м³`, `s = 0.05`, `A = 0.503 м²`). Формула приведена в `docs/02`, раздел 3.2.

**Методика вывода характерных скоростей** — численная, по сетке 0…35 м/с с шагом 0.01:
- `v_min_power = argmin P(v)` — скорость максимальной **продолжительности** полёта;
- `v_max_range = argmin P(v)/v` — скорость максимальной **дальности** (минимум Дж/м).

Результат для параметров статьи — 10.2 и 18.3 м/с. Это расходится с комментарием в
`docs/02` («1–3 м/с» и «10–15 м/с»); подробности — в [agents_energy.md](agents_energy.md).

### 3.2. Модели движения — `agents/kinematics.py` ★

- **Безмассовая кинематика** (MVP-0) — формула из `docs/02`, раздел 3.1:
  `p(t+dt) = p + v_c·normalize(wp − p)·dt`. Классическая «модель частицы с постоянной
  скоростью», стандартная для исследований распределения задач.
- **Двойной интегратор с ограничениями** (MVP-2) — `ṗ = v, v̇ = a` с ограничениями
  `|a| ≤ a_max, |v| ≤ v_max, |ψ̇| ≤ ψ̇_max` (`docs/02`). Двойной интегратор — стандартная модель
  мультиротора в задачах мультиагентной координации. Например, в работе J. van den Berg,
  J. Snape, S. Guy, D. Manocha, *"Reciprocal Collision Avoidance with Acceleration-Velocity
  Obstacles"*, ICRA 2011, именно под такие ограничения строится ORCA-подобное избегание,
  которое потом сделает R2.
- **Профиль торможения** `v ≤ √(2·a_max·d)` — из равнозамедленного движения (`v² = 2ad`):
  максимальная скорость, с которой ещё можно остановиться на расстоянии `d`. Это
  стандартный приём наведения на точку без перелёта (в теории управления — «bang-bang»
  по времени).
- **Ограничение скорости поворота курса** — поворот вектора скорости не больше чем на
  `ψ̇_max·dt` за шаг. Даёт координированный разворот по дуге радиуса `R = v/ψ̇`, как в
  упрощённых моделях наведения БПЛА (см. R. Beard, T. McLain, *Small Unmanned Aircraft:
  Theory and Practice*, Princeton University Press, 2012, главы о моделях наведения).
- **Интегрирование** — метод трапеций для положения: `p += ½(v_old + v_new)·dt`.
  Для двойного интегратора с кусочно-постоянным ускорением это точная формула, а не
  приближение.

### 3.3. Модель обнаружения — `sensing.py` ○ и `world.observe()` ★

- **Формула случайного поиска** `Pd = 1 − exp(−W·L/A)` — классический результат Купмана
  (B. O. Koopman, *"Search and Screening"*, OEG Report No. 56, 1946; переиздание — Pergamon,
  1980). Современное изложение — A. R. Washburn, *Search and Detection*, INFORMS.
  Формула и накопление `Pd_cum = 1 − Π(1 − Pd_k)` взяты из `docs/02`, раздел 3.3.
- **GSD** `= H · pixel_pitch / focal_length` — стандартная формула фотограмметрии
  (разрешение на местности через подобие треугольников «сенсор — объектив — земля»).
- **Ширина кадра** `= 2·H·tan(FOV/2)` — геометрия поля зрения камеры, смотрящей вниз.

### 3.4. Покрытие территории — `missions/search.py` ○

- **«Змейка» (boustrophedon / lawnmower)** — классический метод покрытия прямоугольной
  области параллельными галсами. H. Choset, *"Coverage of Known Spaces: The Boustrophedon
  Cellular Decomposition"*, Autonomous Robots, 2000; обзор — E. Galceran, M. Carreras,
  *"A survey on coverage path planning for robotics"*, Robotics and Autonomous Systems, 2013.
  То, что начинать надо со «змейки», прямо сказано в `docs/02`, раздел 6, п. 3.

### 3.5. Распределение задач — `alloc/roundrobin.py` ○

- Круговое назначение (round-robin) — наивный базовый метод B0 из `docs/03`.
- Класс задачи ST-SR-TA — по таксономии B. Gerkey, M. Matarić, *"A Formal Analysis and
  Taxonomy of Task Allocation in Multi-Robot Systems"*, International Journal of Robotics
  Research, 2004 (упомянута в `docs/01`).
- Для будущего CBBA (R2): H.-L. Choi, L. Brunet, J. How, *"Consensus-Based Decentralized
  Auctions for Robust Task Allocation"*, IEEE Transactions on Robotics, 2009. Интерфейс
  `Allocator` рассчитан на такой алгоритм.

### 3.6. Геометрия — `geometry.py` ★

- **Точка в многоугольнике — метод луча (ray casting, правило чёт/нечет).** Из точки
  пускается горизонтальный луч и считается число пересечений с рёбрами; нечётное число
  означает, что точка внутри. См. E. Haines, *"Point in Polygon Strategies"*, Graphics
  Gems IV, 1994.
- **Пересечение отрезков — тест ориентации (знак векторного произведения)** с обработкой
  коллинеарных случаев. Стандартный алгоритм: T. Cormen et al., *Introduction to
  Algorithms* (CLRS), глава 33.1.
- **Отсечение по ограничивающему прямоугольнику (bounding box)** — дешёвая предпроверка
  перед точной.

### 3.7. Детерминизм и случайные числа — `sim.py` ★

- **NumPy `SeedSequence.spawn()`** — официально рекомендуемый способ получить несколько
  **независимых** потоков случайных чисел из одного зерна (документация NumPy, раздел
  *"Parallel Random Number Generation"*). Генератор по умолчанию — PCG64
  (M. O'Neill, *"PCG: A Family of Simple Fast Space-Efficient Statistically Good Algorithms
  for Random Number Generation"*, 2014).
- **Общие случайные числа (common random numbers)** — приём снижения дисперсии при
  сравнении вариантов в имитационном моделировании: все варианты прогоняются на одинаковых
  случайных входах. A. Law, *Simulation Modeling and Analysis*, McGraw-Hill (глава о
  снижении дисперсии). В `docs/03` это названо «парный дизайн».
- **Время как `t = k·dt`**, а не `t += dt`: так не накапливается ошибка округления чисел
  с плавающей точкой (IEEE 754), и моменты событий воспроизводятся точно.

### 3.8. Статистика в стенде — `experiments/run_matrix.py` ★

- **95 % доверительный интервал** в нормальном приближении: `mean ± 1.96·s/√n`. При 20
  зёрнах это разумная оценка. Для строгого отчёта R4 может заменить её на t-распределение
  (множитель ≈ 2.09 при n = 20) или бутстреп.
- Невалидные прогоны исключаются из статистики, но считаются отдельно — правило из
  `docs/03`, раздел 4.
