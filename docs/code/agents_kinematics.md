# `swarmsim/agents/kinematics.py` — физика движения ★

**Назначение.** Две модели того, как БПЛА перемещается под командой. Обе реализуют общий
интерфейс `MotionSource` (см. [agents_base.md](agents_base.md)) и выбираются в конфиге
полем `agents.motion`. Модели взяты из `docs/02`, раздел 3.1:

| Модель | Этап | Уравнения |
|---|---|---|
| `KinematicMotion` | MVP-0 | `p(t+dt) = p + v_c · normalize(wp − p) · dt` |
| `DoubleIntegratorMotion` | MVP-2 | `ṗ = v,  v̇ = a,  |a| ≤ a_max,  |v| ≤ v_max,  |ψ̇| ≤ ψ̇_max` |

Что **сознательно не моделируется** (`docs/02`, раздел 3.1, «чего не делать»): 6-DOF
(углы крена и тангажа), аэродинамика винтов, моторы, вертикальная динамика. На выводы о
распределении задач это не влияет, а времени съело бы много. Полную динамику даст PX4 SITL
на этапе P6 через тот же интерфейс.

**Импорты.** `math` (скалярные `hypot`, `atan2`, `sqrt`, `cos`, `sin` — на одиночных числах
они в разы быстрее NumPy), `numpy` (векторы), `VehicleState`, `MotionCommand`,
`MotionSource`.

**Система координат.** Плоскость `x, y` в метрах. Курс `ψ` — угол вектора скорости от оси
`x` против часовой стрелки, в радианах `(−π, π]`. Высота `alt` постоянна для агента
(эшелон).

---

## Вспомогательные функции

### `_EPS = 1e-9`
Порог «практически ноль», чтобы не делить на ноль при нормализации.

### `_clip_norm(v, limit) -> np.ndarray`
Ограничение **модуля** вектора с сохранением направления:
`если |v| > limit: v ← v · limit/|v|`. Так ограничиваются и скорость, и ускорение. Обрезать
компоненты по отдельности было бы неправильно: по диагонали тогда можно было бы разогнаться
в √2 раза сильнее.

### `_wrap(a) -> float`
Приведение угла к `[−π, π)`: `(a + π) mod 2π − π`. Нужно, чтобы разница курсов 350° и 10°
считалась как 20°, а не 340°.

---

## `class KinematicMotion(MotionSource)` — безмассовая модель (MVP-0)

### `__init__(p0, alt, v_max, psi0=0)`
Начальное состояние: позиция `p0`, нулевая скорость, курс `psi0`, высота `alt`.

### `step(dt, cmd) -> VehicleState`
Три типа команды:
1. **Скорость** (`cmd.velocity`): `v = clip_norm(v_cmd, v_max)`, мгновенно.
2. **Точка** (`cmd.target`, `cmd.speed`):
   ```
   d = target − p;   dist = |d|
   speed = min(cmd.speed, v_max, dist/dt)      ← dist/dt: не перелететь точку за шаг
   v = d/dist · speed
   ```
3. **Стоп** (пустая команда): `v = 0`.

Затем `p ← p + v·dt`, курс `ψ = atan2(v_y, v_x)`, если скорость не ноль.

Свойства: мгновенный разгон и поворот, путь между точками — отрезок. Этого достаточно для
алгоритмов распределения и покрытия, и это самая быстрая модель.

## `class DoubleIntegratorMotion(MotionSource)` — модель с инерцией (MVP-2)

### `__init__(p0, alt, v_max, a_max, yaw_rate_max, psi0=0, turn_min_speed=0.5)`

| Параметр | По умолчанию в сценарии | Смысл |
|---|---|---|
| `v_max` | 15 м/с | предельная горизонтальная скорость |
| `a_max` | 3 м/с² | предельное горизонтальное ускорение (≈ 0.3 g, умеренно для мультиротора 2–3 кг) |
| `yaw_rate_max` | 90 °/с | предельная скорость поворота **курса** (направления скорости) |
| `turn_min_speed` | 0.5 м/с | ниже этой скорости поворот не ограничен: мультиротор может развернуться на месте, в отличие от самолёта |

### `_desired_velocity(dt, cmd) -> np.ndarray` — наведение
Какую скорость аппарат **хочет** иметь:
- команда скорости → она же (с ограничением `v_max`);
- стоп → ноль;
- точка → направление на точку, модуль
  ```
  speed = min( cmd.speed,  v_max,  √(2·a_max·dist),  dist/dt )
  ```
  Член `√(2·a_max·dist)` — **профиль торможения**. Из равнозамедленного движения
  `v² = 2·a·d`: это наибольшая скорость, с которой аппарат ещё успевает остановиться ровно
  в точке, тормозя с `a_max`. Вдали от точки работает крейсерская скорость, вблизи —
  плавное торможение. Член `dist/dt` не даёт перелететь точку за один шаг.

### `step(dt, cmd) -> VehicleState` — интегрирование
```
v_des = _desired_velocity(dt, cmd)
a     = clip_norm((v_des − v_old)/dt, a_max)    ← хотим за шаг выйти на v_des, но не сильнее a_max
v_new = clip_norm(v_old + a·dt, v_max)
v_new = _limit_turn(v_old, v_new, ψ̇_max·dt)     ← ограничение поворота курса
p     = p + ½·(v_old + v_new)·dt                ← метод трапеций
ψ     = atan2(v_new)
```
Почему трапеция. При постоянном на шаге ускорении `p(t+dt) = p + v·dt + ½·a·dt²`, а это
в точности `p + ½(v_old + v_new)·dt`. Формула точная, а не приближённая. Явный метод
Эйлера (`p += v_new·dt`) давал бы систематическую ошибку.

### `_limit_turn(v_old, v_new, max_dpsi) -> np.ndarray` — ограничение поворота
1. Если старая скорость меньше `turn_min_speed` или новая почти ноль — без ограничения.
2. Иначе считается угол поворота `Δψ = wrap(atan2(v_new) − atan2(v_old))`.
3. Если `|Δψ| > ψ̇_max·dt`, вектор `v_new` **поворачивается** к старому курсу до угла
   ровно `ψ̇_max·dt`, **модуль сохраняется**.

Почему ограничение ускорения при этом не нарушается. Расстояние между векторами одинаковой
длины `|v_new − v_old|² = |v_new|² + |v_old|² − 2|v_new||v_old|·cos θ` убывает при
уменьшении угла `θ` между ними. Поворот к старому курсу только уменьшает `|v_new − v_old|`,
значит `|a| ≤ a_max` остаётся верным. Это проверяется тестом на 3000 случайных командах.

Физический смысл: при скорости `v` минимальный радиус разворота `R = v / ψ̇_max`. На
12 м/с и 90 °/с это ≈ 7.6 м. На концах галсов «змейки» аппарат тормозит (профиль
торможения) и разворачивается по небольшой дуге. Отсюда разница времени миссии:
805 с против 651 с у безмассовой модели в `baseline`.

## Как добавить свою модель
Унаследоваться от `MotionSource`, хранить `self._state: VehicleState`, реализовать
`step(dt, cmd)`, добавить вариант в `AgentsConfig.motion` (`scenario.py`) и ветку в
`SimLoop._build_agents`. Так же будет подключён `MavsdkMotion` для PX4: команда «точка» →
`goto_location`, «скорость» → `set_velocity_ned`, `state` ← телеметрия.
