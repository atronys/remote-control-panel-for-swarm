# `swarmsim/planning/` — общая целевая функция, маршруты, проверка плана (P2)

Все распределители (B0–B5) планируют по **одной** модели — docs/03 §8, правило 2–3: одинаковая
информация и одинаковая цель, иначе сравнение архитектур теряет смысл.

## `routing.py`
* `TaskGeom.build(tasks, ids)` — геометрия задач для планирования: точка входа/выхода, длина
  маршрута внутри задачи, ценность, матрица «выход i → вход j». `remaining(task, progress)` —
  сколько осталось у начатой задачи (прогресс по путевым точкам сохраняется при передаче).
* `agent_context(state, tasks, energy, reserve, e_land)` → `AgentCtx`: откуда стартует агент
  (конец текущей задачи), когда (`t0`), сколько энергии доступно с учётом возврата и резерва,
  что уже заблокировано (выполняемая задача).
* `RouteModel(geom, discount)`:
  * `evaluate(ctx, route)` → `RouteEval(score, completion, energy, feasible, t_return)`;
    **score = Σ value_j · λ^{C_j}** — ценность задачи дисконтируется временем её завершения
    (`planning.discount` λ = 0.998 за секунду);
  * `feasible` — хватает ли энергии на весь маршрут, возврат домой, посадку и резерв;
  * `insertion(ctx, route, cands, ev)` — прирост score при вставке каждого кандидата в каждую
    позицию (векторно, суффиксные суммы), основа жадного аукциона и CBBA;
  * `improve` — локальное улучшение (relocate).

## `objective.py`
* `sector_values(world, tasks)` — ценность сектора = доля априорной вероятности целей в нём
  (Pd-планирование); `planning.value: uniform` — ценность 1 (планирование «по покрытию», абляция A3).
* `true_values(world, tasks)` — по **истинным** целям: только для оракула B0.
* `mission_utility(tasks, E_Wh, cfg)` → `U`, `U_norm`, `U_ontime`:
  `U(M) = Σ priority·1[выполнено до deadline] − λ_E·E_total − λ_T·makespan` (docs/03 §4;
  deadline 900 с, λ_E = 0.01 на Вт·ч, λ_T = 0.005 на с).

## `validator.py` — `PlanValidator` (SR-6)
Перед исполнением любой план проверяется: дубли задач между агентами, энергия (весь хвост плана
с возвратом и резервом), геозона, эшелон. `safety.plan_validation`: `repair` — отрезать
недопустимый хвост (задачи уходят в пул), `log` — только записать, `off`. Нарушения пишутся
событием `plan_violation` и считаются в `N_plan_energy`, `N_plan_geo` — это метрика качества
распределителя, а не только защита.
