# Связь, знание и децентрализация: `network.py`, `knowledge.py`, `decentral.py` (P4)

Включается `comms.kind: network` или распределителем `cbba` / `hybrid`. Свой поток RNG
(6-й потомок зерна) — прежние прогоны не меняются (регрессия бит-в-бит).

## `network.py` — `Network`
* узлы: агенты 0..N−1 и станция N; связь есть, если расстояние ≤ `range` (агент–агент) или
  `range_gcs` (агент–станция) и станция не в разрыве (`gcs_outages: [[t0, t1], …]`);
* сообщение: задержка `latency ± jitter`, потеря с вероятностью `loss` (`loss_gcs` для станции),
  очередь по полосе `bandwidth` (байт/с на отправителя);
* heartbeat 5 Гц (`hb_period`), gossip живости 1 Гц;
* `stats` → `N_msg`, `B_per_agent` (байт/с на агента) по типам: state, bids, plan, event.

## `knowledge.py` — `KnowledgeBase`: что знает каждый наблюдатель
Реплика у каждого агента и у станции: кто жив, где кто, чем занят, статусы задач
(свободна / назначена / выполняется / выполнена), владелец, прогресс.
* **«выполнена» монотонна** и распространяется транзитом (множество выполненного едет в heartbeat);
* **владелец выполняемой задачи не перезаписывается проигравшим конфликт** (больший прогресс,
  при равенстве — меньший номер) — иначе проигравший, уступив, «освобождает» чужую задачу у всех;
* конфликт исполнения (двое выполняют одно) фиксируется при приёме heartbeat → `conflicts`.
* `detect(t, timeouts)` — кто потерян. Матрица таймаутов строит `NetworkRuntime._timeouts`.

## Обнаружение отказа с учётом дальности (`NetworkRuntime._timeouts`)
Сколько наблюдатель o ждёт вестей от агента a:
* a (последняя известная позиция ± сколько мог пролететь с тех пор) в зоне связи **самого** o —
  `detect_timeout` (1.5 с);
* в зоне кого-то, кого o слышит, — `relay_timeout` (4 с): вести идут через gossip, стареют ~1 с на переход;
* вне зоны всех — `lost_hard_timeout` (60 с): молчание объяснимо дальностью, это не отказ;
* станция во время собственного разрыва никого не теряет.

Без этого рой, разделённый дальностью на группы, считал соседей из другой группы погибшими
и брал их выполняемые задачи → дубли. С этим в P4 `N_dup = 0` и при дальности 400–600 м на поле 1 км.

## `decentral.py` — `NetworkRuntime`
Каждый шаг: `step_begin` (heartbeat, доставка, обнаружение, режим NO_GCS) → агенты →
`after_agents` (свои события → своё знание и узел CBBA; «моя задача уже выполнена другим» →
бросить; конфликты исполнения → уступает меньший прогресс; узлы CBBA).
* **центр (B2)**: станция планирует по своей реплике (`gcs_snapshot`, `gcs_tasks`), план
  доставляется сообщением с версией и повтором раз в секунду до подтверждения;
* **CBBA (B4)**: пересчёт пакета только если что-то изменилось; кандидаты — не выполненные и
  не выполняемые живым владельцем; рассылка при изменении (не чаще `min_gap`) и раз в `period`;
  уходящий домой / севший агент один раз рассылает отказ от заявок;
* **гибрид (B5)**: план от станции; агенты без связи со станцией торгуются CBBA только за свободное.
* summary: `N_lost` (невыполненные, которых нет ни в одном плане живого), `N_conflict_yield`,
  `N_false_loss`, `A_gcs` (темп выполнения в разрыве / вне), `done_in_outage`,
  `node_ms_mean/max` (бортовой пересчёт пакета).

Тесты: `tests/test_network.py`. Контрольная точка: `docs/reports/P4_comms.md`.
