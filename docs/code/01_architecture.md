# Архитектура: как всё связано

## 1. Слои

```
 ┌──────────────────────────────────────────────────────────────┐
 │  apps/cli.py  ·  experiments/run_matrix.py  ·  apps/viz.py   │  запуск, серии, картинки
 └──────────────────────────────┬───────────────────────────────┘
                                │ Scenario + seed
 ┌──────────────────────────────▼───────────────────────────────┐
 │  swarmsim/sim.py  — SimLoop (ЯДРО)                           │
 │    строит мир, агентов, задачи, плагины; крутит цикл; журнал │
 └───┬───────────┬────────────┬───────────┬──────────┬──────────┘
     │           │            │           │          │
 ┌───▼───┐  ┌────▼─────┐ ┌────▼────┐ ┌────▼───┐ ┌────▼─────┐
 │ World │  │ Agent ×N │ │Allocator│ │ Comms  │ │ Faults   │   ← через interfaces.py
 │world.py│ │agents/   │ │ alloc/  │ │comms.py│ │faults.py │
 └───┬───┘  └────┬─────┘ └─────────┘ └────────┘ └──────────┘
     │           │ MotionSource
     │      ┌────▼────────────────┐   ┌─────────────────┐
     │      │ kinematics.py       │   │ energy.py       │
     │      │ Kinematic / DoubleI │   │ RotaryWingEnergy│
     │      └─────────────────────┘   └─────────────────┘
 ┌───▼────────┐  ┌────────────┐  ┌────────────┐
 │ sensing.py │  │geometry.py │  │ metrics.py │
 └────────────┘  └────────────┘  └────────────┘
         общие типы: datatypes.py   ·   конфиг: scenario.py   ·   запись: io.py
```

Правило зависимостей: **ядро знает только интерфейсы** (`interfaces.py`) и общие типы
(`datatypes.py`). Конкретный распределитель, модель связи и т. д. выбираются по имени из
конфига через реестр. Поэтому R2 может написать CBBA, не открывая `sim.py`.

## 2. Жизненный цикл одного прогона

```
run(scenario, seed)
 │
 ├─ SimLoop.__init__
 │   ├─ make_rngs(seed)            → 5 независимых генераторов: world, sensing, comms, faults, alloc
 │   ├─ World(...)                 → сетка, бесполётные зоны, карта вероятности, ВСЕ цели заранее
 │   ├─ SensorModel, RotaryWingEnergy
 │   ├─ _build_agents()            → N агентов: дом, эшелон высоты, модель движения
 │   ├─ mission.decompose(world)   → TaskSet (секторы со «змейкой»)
 │   └─ allocator, comms, faults, metrics — из реестра по kind
 │
 └─ SimLoop.run
     ├─ _allocate(0, "initial")    → первичное назначение (с проверкой)
     ├─ agent.takeoff(0)  для всех
     └─ цикл k = 0 … n_steps−1,  t = k·dt:
         1) faults.inject_due(t)        → agent.fail() → задачи освобождаются
         2) comms.step(t)               → соседи, доставка сообщений
         3) allocator.should_trigger(…) → при «да» _allocate(t, "trigger")
         4) для каждого агента:
              agent.step(t, dt, …)      → команда → MotionSource.step → энергия → прогресс по точкам
              world.observe(agent)      → Pd по пройденным ячейкам, обнаружение целей
         5) world.step(dt)              → появление новых целей
            world.check_separation()    → столкновения / опасные сближения
            world.check_geofence()      → геозоны и границы
            metrics.record(t+dt)        → временные ряды, T_detect
         выход, если никто не в воздухе
     └─ metrics.finalize() + манифест → RunResult
```

## 3. Детерминизм — на чём держится

| Механизм | Где | Что защищает |
|---|---|---|
| Фиксированный `dt`, `t = k·dt` | `sim.py` | нет накопления ошибки округления |
| Отдельные потоки RNG из `SeedSequence` | `sim.make_rngs` | изменение одного модуля (например, сенсора) не меняет мир |
| Все цели генерируются при создании мира | `World.__init__` | мир не зависит от того, как шла симуляция |
| Фиксированный порядок шагов и агентов | `SimLoop.run` | одинаковый порядок потребления случайных чисел |
| Словари с порядком вставки, `sorted()` в назначениях | везде | порядок обхода не зависит от хэшей |
| Ничего не зависит от настенного времени | везде | `wall_time_s` пишется в отчёт, но исключён из сравнения (`WALLCLOCK_FIELDS`) |

Проверено тестом `test_determinism_same_seed_same_numbers` для обеих моделей движения:
совпадают summary, журнал событий, временные ряды и траектории.

## 4. Где что хранится во время прогона

| Данные | Хозяин | Кто читает |
|---|---|---|
| Положение, скорость, курс, высота | `MotionSource._state` (`VehicleState`) | агент, мир, метрики |
| Энергия, режим, план, текущая задача | `Agent` | ядро, распределитель (через `AgentState`) |
| Статусы задач, владелец, время выполнения | `Task` в `TaskSet` | все |
| Цели, карта покрытия, счётчики нарушений | `World` | метрики |
| События | `EventLog` | распределитель (`should_trigger`), запись в `events.jsonl` |

Распределитель получает **снимок** (`WorldSnapshot` с неизменяемыми `AgentState`), а не
живые объекты: так он не может случайно изменить состояние агента в обход ядра.
