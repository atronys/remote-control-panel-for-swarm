# `swarmsim/comms.py` — модель связи ○ (владелец R3)

**Назначение.** Реализация `CommsBus` для MVP-0/1: идеальный канал с ограниченной
дальностью. Полная модель (задержка, дрожание, потери, полоса, разрывы) — задача R3 на
MVP-2 по `docs/02`, раздел 3.4.

**Импорты.** NumPy, `CommsBus`, `register_comms`.

## `@register_comms("ideal") class IdealComms(CommsBus)`
Параметр из YAML: `range` (м, по умолчанию «бесконечность»):
`comms: {kind: ideal, range: 2000}`.

| Метод | Что делает |
|---|---|
| `step(t, agents)` | по живым агентам строит матрицу расстояний (NumPy) и граф соседей `|p_i − p_j| ≤ range`; доставляет сообщения, отправленные на прошлом шаге, **если получатель всё ещё в радиусе** |
| `send(src, dst, msg)` | кладёт сообщение в очередь (доставка на следующем шаге) |
| `broadcast(src, msg)` | `send` всем текущим соседям |
| `neighbors_of(id)` | список соседей (ядро передаёт их фильтру безопасности) |
| `inbox(id)` | сообщения, доставленные на этом шаге (с полем `src`) |
| `stats()` | `{"N_msg": ...}` — попадает в summary |

`gcs_reachable()` не переопределён — связь с наземной станцией есть всегда.

## Что сделает R3
Задержка `base + jitter + size/bandwidth` с очередью, независимые потери с вероятностью
`p_loss` (через свой `rng`), подсчёт байт (метрика `B`), разрывы по расписанию,
`gcs_reachable() = False` во время разрыва (эксперимент H2 из `docs/03`).
