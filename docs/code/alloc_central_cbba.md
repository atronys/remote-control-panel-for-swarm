# `swarmsim/alloc/` — распределители B0–B5 (P2–P4)

| Имя в сценарии | Обозн. | Файл | Суть |
|---|---|---|---|
| `static_oracle` | B0 | `cpsat.py` | оптимизатор по **истинным** целям до вылета, без перераспределения |
| `static_roundrobin` | B1 | `roundrobin.py` | секторы по кругу, без динамики |
| `central_greedy` | B2 | `central.py` | жадный аукцион на станции, пересчёт по событиям |
| `central_optimal` | B3 | `cpsat.py` | жадный → CP-SAT (≤ 12 задач) → LNS |
| `cbba` | B4 | `cbba.py` | CBBA на бортах, без центра |
| `hybrid` | B5 | `cbba.py` | B2, а у потерявших станцию — CBBA среди «сирот» |

## `central.py`
* `CentralAllocator` — общий каркас: `replan: full | repair` (всё заново или только освободившееся),
  `dynamic` (пересчитывать ли по событиям: отказ, новая цель, отклонение от плана, низкий заряд),
  `interrupt` — FR-9: новая срочная цель может прервать текущую задачу ближайшего агента
  (прогресс прерванной сохраняется). `should_trigger` не реагирует на тихий отказ, пока его не заметили.
* `greedy_insert` — последовательный аукцион: на каждом шаге вставка с наибольшим приростом score
  среди всех (агент, задача, позиция), только допустимые по энергии.
* `ruin_recreate(model, ctxs, routes, rng, iters, frac)` — LNS: снять долю задач, вставить жадно,
  принять если лучше. Используется как «лучшее известное» в P2 (на малых задачах совпадает с CP-SAT).

## `cpsat.py`
* `solve_cpsat` — точная модель OR-Tools CP-SAT: у каждого агента `AddCircuit` по своим задачам,
  время завершения через `AddElement` по таблицам дисконта; детерминированное время решения,
  подсказка — жадное решение.
* `CentralOptimal` (B3), `StaticOracle` (B0, `values_override = true_values`, `dynamic = False`).

## `cbba.py` — Consensus-Based Bundle Algorithm (Choi, Brunet, How, 2009), асинхронный вариант
* `cbba_actions` — таблица правил консенсуса (update / reset / leave) векторно по задачам.
* `CBBANode` — узел на борту: `y` (ставки), `z` (победители), `s` (свежесть сведений о каждом агенте),
  пакет и путь.
  * **ставки в абсолютном времени миссии** (`ctx.t0 += t`) — иначе ставки разных моментов
    несравнимы и консенсус «дрожит»;
  * **гистерезис 5 %** — чужая ставка должна быть заметно лучше, чтобы отнять задачу;
  * специальные ставки **RUN** («выполняю», перебить нельзя) и **DONE** («выполнено»);
  * `release_peer(k)` — сосед потерян: его заявки сброшены, и заявки от его имени, пришедшие
    транзитом, игнорируются (`merge` фильтрует) — иначе соседи «воскрешают» мёртвого;
  * `reset_claims` — отказ от всех заявок (новый план от станции, уход домой, посадка);
  * `drop(j)` — узел снимает заявку, которую агент выполнить не может (по своему знанию).
* `CBBAAllocator` (B4, `decentralized = True`), `HybridAllocator` (B5, `hybrid = True`, внутри — B2).
  Сами ничего не распределяют: узлы крутит `NetworkRuntime` (см. `network_knowledge.md`).

Тесты: `tests/test_planning.py` (P2), `tests/test_network.py` (правила CBBA, RUN/DONE, фильтр потерянных).
Контрольные точки: `docs/reports/P2_allocation.md`, `P4_comms.md`.
