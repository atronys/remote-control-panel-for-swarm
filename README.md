# SwarmCore — симулятор роя БПЛА

Симулятор группы дронов, которые вместе обследуют территорию (поиск целей). Он проверяет,
как рой делит задачи между дронами и что происходит, когда:

- дроны отказывают, а их задачи нужно передать другим;
- по ходу миссии появляются новые цели;
- пропадает связь с наземной станцией или теряются пакеты;
- дроны сближаются и должны разойтись без столкновений.

Сравниваются шесть способов распределения задач: от «всё решает станция» до «дроны
договариваются сами, без центра».

| Код | Способ | Суть |
|---|---|---|
| B0 | `static_oracle` | план до вылета, «знает», где цели (ориентир сверху) |
| B1 | `static_roundrobin` | секторы по кругу, без перераспределения |
| B2 | `central_greedy` | станция распределяет и пересчитывает при событиях |
| B3 | `central_optimal` | станция с оптимизатором (CP-SAT) |
| B4 | `cbba` | дроны торгуются за задачи между собой, без центра |
| B5 | `hybrid` | работает станция, а без связи с ней дроны договариваются сами |

## Установка

Нужен Python 3.10 или новее.

```powershell
git clone https://github.com/atronys/<репозиторий>.git
cd <репозиторий>
python -m venv .venv
.venv\Scripts\Activate.ps1          # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev,research]"
```

## Запуск

**Пульт в браузере (проще всего):**

```powershell
swarmcore serve
```

Откроется страница: слева настройки (алгоритм, число дронов, отказы, связь, ветер),
кнопка **«Новый прогон»**, справа — анимация полёта и итоги. Остановить — `Ctrl+C`.

**Один прогон из командной строки:**

```powershell
swarmcore run --scenario scenarios/demo.yaml --replay
```

Результаты попадают в папку `runs/…`. `replay.html` в ней — анимация, её открывают в браузере.
Без `--seed` каждый прогон новый, с `--seed N` прогон повторяется точь-в-точь.

Полезные параметры:

| Что | Как |
|---|---|
| выбрать алгоритм | `--allocator cbba` (или `hybrid`, `central_greedy`, …) |
| число дронов | `--set agents.count=20` |
| потери пакетов 30 % | `--set comms.kind=network --set comms.loss=0.3` |
| хронология событий | `swarmcore log runs/<папка>` |

Сценарии лежат в `scenarios/`:
- `demo` — «живой» мир: ветер, случайные отказы, разрыв связи;
- `baseline` — базовый воспроизводимый сценарий для экспериментов;
- `failures` — сценарий с отказами дронов;
- `nofly` — с запретными для полёта зонами.

**Тесты:**

```powershell
python -m pytest -q
```

**Эксперименты** (контрольные точки дорожной карты; каждая команда пишет отчёт в `docs/reports/`):

```powershell
python -m experiments.gates p3 --jobs 8     # отказы и новые цели, ~10 мин
python -m experiments.gates p4 --jobs 8     # разрыв связи со станцией, ~1 ч
python -m experiments.gates p5 --jobs 8     # сравнение всех способов, ~2.5 ч
```

`--jobs` — сколько ядер процессора использовать.

## Главные результаты

- Все способы с перераспределением (B2, B4, B5) довели миссию до конца даже при отказе 30 % дронов.
- Без связи со станцией центр (B2) ждёт её возвращения около 150 с. Рой (B4, B5) подхватывает
  задачи отказавшего за 1.5 с, без дублей и потерянных задач.
- В нормальных условиях качество всех способов почти одинаково (разница меньше 1 %).
  Гибрид B5 при этом передаёт по радио примерно на 40 % меньше данных, чем чистый рой B4.
  Поэтому он выбран для переноса на бортовой компьютер.
- Уклонение от столкновений (ORCA) нужно, только если дроны летят на одной высоте.

## Структура

```
swarmsim/          симулятор
  planning/        общая целевая функция, маршруты, проверка плана
  alloc/           способы распределения B0–B5
  agents/          дрон: движение, энергия, уклонение (ORCA)
  network.py       модель радиосвязи
  knowledge.py     что знает каждый дрон
  decentral.py     работа без центра (CBBA, гибрид)
apps/              командная строка, анимация, пульт в браузере
experiments/       эксперименты и статистика
scenarios/         сценарии
tests/             тесты
docs/              концепция, требования, программа экспериментов, дорожная карта
docs/code/         описание каждого файла кода
```

Подробнее: цель и гипотезы проекта — `docs/03_experiment_program.md`, дорожная карта —
`docs/05_roadmap.md`.
